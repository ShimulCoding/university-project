# Workload model

Generated by node scripts/scalability/workload-model.mjs --document. Values are explicit assumptions, not telemetry or measured capacity. Concurrent people/sessions are not simultaneous open requests. RPS = active users × transport requests per cycle ÷ cycle seconds. Multiply again by measured SSR/SQL fan-out when sizing those tiers; never silently count them as one. Static assets, retries, login arrivals and browser PDF work require separate measurement.

## Fifty thousand active users: independent journey targets

Each row assigns all 50,000 users to that journey to expose its demand. These mutually exclusive scenarios must not be added together. Financial Controller/System Admin rows are stress envelopes, not a prediction that all students hold those roles.

| report-generation | 900s | 0.333 | 0 | 277.778 | 277.778 | 0:5 |

- **public-publication:** An active visitor makes three public API requests per minute during a publication burst.
- **event-registration-and-fee-evidence:** One already authenticated student registers and uploads one fake payment-evidence file in five minutes. This is evidence submission, not external payment settlement.
- **event-finance-dashboard:** Five authenticated dashboard/list API requests per minute; report writes are budgeted separately.
- **ordinary-student-login:** One initial password sign-in per five-minute arrival wave. Students without an enrolled factor do not require MFA.
- **enrolled-mfa-login:** System Admin transport shown; event teams use event-team-login and enrolled students use login. MFA is real TOTP, not enrollment bypass or reusable recovery fixtures.
- **report-generation:** Upper existing account budget: five reports per fifteen minutes. Per-process report admission may shed this target; that is a measurement, not a reason to weaken it.

The enrolled-MFA scenario does not auto-enroll or bypass a factor. Load fixtures use their own real TOTP factors and unique accounts; tokens/codes are never logged. The basic student scenario reflects current optional student MFA. Financial evidence upload is not gateway payment settlement. At the all-student registration envelope, one upload per cycle yields 166.667 uploads/second. File sizes/parts must be varied and reported separately; no bandwidth or scanner capacity is assumed.

## Mixed active cohorts

Explicit hypothetical mix: 90% public browsing, 9.9% registration/evidence and 0.1% event finance dashboards, with each person's journey frequency above. The fractions sum to one. Fifty thousand active users yield 2,353.167 read RPS and 33 write RPS, total 2,386.167 API RPS. ## Initial acceptance targets

These are proposed SLO test thresholds, not achieved results: public JSON p95 ≤300ms/p99 ≤1s; authenticated read p95 ≤1s/p99 ≤2s; registration/ledger mutation p95 ≤1.5s/p99 ≤3s; password/MFA each p95 ≤2s/p99 ≤4s; valid offered-load errors (including shed 429/503) <1%. Uploaded-byte completion, scanner outcome and client PDF generation have separate size-dependent distributions. Do not exclude legitimate shedding from error rate to make a capacity target pass. Preserve security budgets, bcrypt cost, authority and financial invariants when a threshold is missed.

## Absent journeys and validation limits

- **academic-results-and-grade-changes: N/A.** No academic result/grade page, route or model exists in the source inventory.
- **payment-gateway-and-webhook: N/A.** Current money flow reviews uploaded evidence/manual records; no gateway or webhook exists.
- **server-pdf-render: N/A.** PDFKit generates browser-local exports using fixed fonts. HTTP asset traffic and browser CPU/memory need browser measurements, not a nonexistent rendering API.
- **sms-and-bulk-import: N/A.** No SMS integration or import worker exists.

Use publication-day public browsing as the existing read-heavy scenario; it is not an academic results feature. The map covers every current source entry and this script rejects unmapped transport routes. Phase 2 must measure actual page/API/SQL request fan-out, arrival vs closed-loop think-time behavior, retry amplification, file/PDF sizes, cache-hit ratios, CPU/RSS/event-loop/connection pressure and first bottleneck on fixed fake datasets. Phase 9 validates this model with average/stress/spike/soak/breakpoint tests. Native Windows and limited Linux/Compose are separate environments. A 2 CPU/4 GB VPS has not been measured or deployed.
