## Manual release requirements and residual risk

Follow [security-operator-handoff.md](security-operator-handoff.md) and the reviewed [runtime grants](security-runtime-grants.sql). These steps are **not executed**: privileged onboarding/old event-team assignment; separate database runtime/migration identities; verified network/HTTPS/proxy/firewall policy; real private ClamAV/signatures and SMTP sender delivery; encrypted consistent database/file/key backups with an isolated restore; external audit collector/alerts and incident handling. No rotation of real credentials was justified by the committed-secret scan; preserve the MFA key until a planned re-encryption/enrollment procedure exists.

A human penetration test should use disposable staging accounts/events and cover all role combinations/direct IDs and revocation races, alternate MFA/reset/recovery paths, same-origin/sibling-origin CSRF/XSS and browser engines, malformed/polyglot/PDF/image files, path/symlink/OS boundaries, concurrent financial transitions and interrupted uploads, shared-store limits/slow clients/large ledgers, the actual TLS/IAM/firewall/SMTP/storage configuration, and backup/restore plus supervised lost-factor/incident drills. Do not run aggressive tests against real data or an unidentified production deployment.

OWASP ZAP was not run: no ZAP/Java/Docker installation or identified staging target was available. Actual loopback HTTP attacks and Edge browser tests are recorded; this does not substitute for comprehensive authenticated DAST or a human penetration test. Full existing-demo runtime verification also remains unavailable without operator-enrolled real privileged accounts/private MFA codes; its contract tests and isolated MFA/browser suites passed without enrolling those accounts.
